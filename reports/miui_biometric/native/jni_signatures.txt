## 4. Detect callback path (st_auth_set_facedetect_callback)

Java  FaceAuthManager.setCallback(cb)            sources/faceauth/.../FaceAuthManager.java
  -> FaceAuthNative.enableFaceDetectCallback(true)   (0x3a1c: sets g_enable_facedetect_callback)
  -> on every enroll()/auth() call the JNI layer does
       st_auth_set_facedetect_callback(g_enable ? FaceDetectCallBack : NULL)
  -> st_auth_set_facedetect_callback (libstfaceunlockocl 0x10dfd8) wraps the raw
     fn pointer in std::function<void(st_detect_t*)> and forwards to
     stfaceunlock::FaceUnlock2DInterFace::SetFaceDetectCallback (0x1483e0)
  -> fired from the native detect stage on a native worker thread, so
     FaceDetectCallBack (0x3420) does GetEnv(JNI_VERSION_1_6) and
     AttachCurrentThread when needed, converts st_detect_t ->
     FaceDetectedInfo(mIsDetected, mFaceRect) and calls
     FaceAuthNative.onFaceDetected(...) via CallStaticVoidMethod.
  Note: no caller of FaceAuthManager.setCallback exists among the decompiled
  integration classes (FaceUnlockManager, FaceEnrollHelper, FaceAuthenHelper,
  MiuiFaceService); in the FaceUnlockManager/FaceEnrollHelper paths the pointer
  therefore stays NULL and no Java detect callback is delivered.

## 5. Return/status conventions (confirmed)

- st_result_t 0            = ST_OK
- 201 ST_FACE_AUTH_STATUS_UNLOCK_OK   -> FaceAuthManager maps to app code 0
- 202 ST_FACE_AUTH_STATUS_UNLOCK_FAILED -> app code 12
- 1   ST_FACE_AUTH_STATUS_DETECT_NO_FACE -> app code 5 (FaceUnlockManager treats
      "compare() != 5" as "a face was present" for the failure message)
- -2  ST_E_HANDLE          -> app code 2 (handle not initialised)
- -1008/-1001 TEMPLATE_FILE_UPPER_LIMIT / DAMAGED -> app codes 35 / 34
- the *rc[0] out-parameter always receives the raw native status; the JNI int
  return is a payload (face id / unlock id) or the status for pass-through calls.
