# JAX reimplementation — weak-signal forecast

TFLite model: `../models/0.3_new_0410_less.tflite` (112,544 B, TFL3, MLIR-converted).
Weights: all real, extracted from the flatbuffer into `params.npz` (float16
storage, dequantized to float32 at inference). No training is involved.

## Preprocessing contract (confirmed in Java)

For each 100 ms tick the service appends `(RSRP dBm, RSRQ dB, SINR dB, PCI-changed)`.
When 100 samples are available every 1 s:

```
x[0][  0:100][0] = medianFilter5(RSRP)
x[0][100:200][0] = medianFilter5(RSRQ)
x[0][200:300][0] = medianFilter5(SINR)
x[0][300:400][0] = PCI-changed  (1.0 if PCI differs from previous sample, else 0.0)
```

* No normalization, mean subtraction, or scaling: raw dB values and 0/1 flags.
* Median window 5 with clipped (shrinking) windows at both ends, not
  edge-replicated padding. Even-length windows average the two middle values.
* The PCI *value* is not an input; only the change indicator is.
* Output: `softmax[2]`; Java takes `output[0][1] < 0.5 ? "WEAK" : "STRONG"`,
  so class 1 = STRONG, class 0 = WEAK.

The model is a radio-signal classifier, not an audio classifier. The app's
`mtb_auto_anasys_tool_audio_*` strings are unrelated UI resources; the only
model call site is `AiWeakSignalForecastService`.

## Verification result

`verify_tflite_jax.py` reports max_abs 0 on random input and 1.49e-08 on a
derived (median-filtered) series. `verify_derived.py` covers 58 mixed cases
(zeros, random uniform/normal, raw-dB constants, 54 synthetic series) with
worst max_abs 1.42e-06, 0 failures, tolerance 1e-4.
